# Big x Reality｜CIS 品牌資產與 AI Presentation Skill

> **專案定位：**這裡不是單純的 CIS 檔案倉庫，也不是一份固定的 PowerPoint 範本，而是全球動力科技（**Big x Reality**）統一管理**企業識別、正式設計素材、簡報版型與 AI 生成規則**的公司共用資產庫。
>
> **目前狀態：**CIS v3.2 品牌素材已備齊；AI Presentation Skill 尚處於規格與開發階段，**目前不能宣稱已具備自然語言直接生成完整 PPTX 的功能**。

## 1. 我們為什麼要建立這個專案？

公司同仁日常需要製作產品介紹、內部工作報告、客戶提案、國防與警政及消防訓練方案、展覽成果、年度行銷規劃等簡報。過去每次都需人工找圖片、套版、修改樣式，簡報品質也容易因個人習慣而不一致。

**最終目標：同仁只要在 Claude 提供主題、受眾、語言、頁數與必要資料，系統就能運用公司 CIS 及已審核的原生 PPTX 版型，產生完整、精美、符合品牌且可編輯的 PowerPoint 簡報。**

例如：

> 幫我做一份 15 頁英文簡報，介紹 Big x Reality 的 XR 警察訓練方案，對象是海外警政機關。內容以產品功能、操作情境、訓練價值和導入流程為主，使用公司的 CIS，保留專業的版型與適當動畫。

### 完成後應該具備的能力

1. **理解需求**：區分內部／外部簡報、聽眾、產業、語言、內容與頁數。
2. **組織內容**：建立有邏輯的內容大綱與每頁重點；不得虛構公司、產品及財務數據。
3. **搜尋合適版型**：從已建索引的商用 PowerPoint 素材與 BXR 核准版型挑選，而非每次用簡單方塊從零拼裝。
4. **遵循 CIS**：套用官方 Logo、字體、品牌色、產業輔助色與品牌影像規範。
5. **產生原生 PPTX**：標題、內文、表格與可行的圖表使用 PowerPoint 可編輯物件，不把整頁文字烘焙成圖片。
6. **妥善保留原始設計**：合理延用既有母片、版型與動畫；無法保留的效果需標示並驗證替代方案。
7. **自動品質檢查**：實際渲染與檢查文字溢出、圖像裁切、對齊、範例殘留、品牌錯誤及檔案可開啟性。
8. **交付成果**：完整 PPTX，必要時附 PDF 預覽、使用版型來源及品質檢查紀錄。

### 設計分工

- **ChatGPT**：專案規格、資料與版型索引、CIS 規則彙整、品質驗收規劃、必要的品牌視覺素材製作。
- **Claude Code**：PPTX 編輯與轉換引擎、版型智慧選擇、動畫相容性處理、簡報生成、渲染與自動化測試。
- **公司同仁**：提出簡報需求、提供正確內容與事實資料、審核最後成果。

> 第一版優先讓 **Claude Code** 可以生成與驗證可編輯簡報；將相同工作流程提供給只使用 **Claude 網頁版** 的同仁，是後續需要評估執行環境與權限的目標，不應視為已完成。

## 4. 原始 PPTX 素材與自動產生系統

已提供供盤點的外部設計素材來源包括 `500頁.pptx` 與 `Aviation Slides.zip`。這些**並不是已清理的 BXR 官方版型**，而是未來轉換用的原始設計參考。

設計流程應區分：

`原始素材（不可覆寫） → 結構及視覺分類 → CIS 轉換 → 人工/自動驗收 → BXR 核准版型 → 自然語言生成簡報`

**原始素材的來源字樣、展示文字、示範公司資料與圖片，必須依授權清理；授權要求保留的署名或聲明不可擅自移除。** 轉換後的核准版型必須與原始檔分開管理。

**本 GitHub Repository 目前為公開狀態。** 在確認授權前，請勿提交受限制的商用 PPTX 原始素材、機密簡報及未授權字體。Git LFS 只解決大型檔案管理問題，不能提供機密保護。

## 5. 開發順序（供 Claude Code 閱讀）

| 階段 | 工作 | 完成標準 |
|---|---|---|
| P0 | 確認 CIS 資料、版型索引、授權與原始檔管理 | 資產來源可追溯，路徑清楚 |
| P1 | 分析兩批 PPTX 原始素材 | 版型分類、縮圖、頁面物件、動畫標記 |
| P2 | 選取 5 頁做 CIS 轉換試驗 | 原始／修改後對照、原生可編輯、檢查報告 |
| P3 | 擴充 30–50 頁核准版型 | 各種簡報用途與產業均有可用版型 |
| P4 | 開發自然語言生成 PPTX | 可依簡報需求生成完整、可編輯文件 |
| P5 | 實測與公司導入 | 可重複使用、排版穩定、品質驗收合格 |

> **成功標準不是生成一張漂亮的簡報圖片，而是交付具有完整內容邏輯、專業排版、可編輯文字與可驗證動畫的 PowerPoint 檔。**

## 6. 版本與開發原則

- `main`：正式資產與完成審核的功能。
- `dev/*`：功能開發，透過 Pull Request 送審。
- 官方 CIS 原始圖檔與 v3.2 指南應保持完整；不任意重命名已被引用的媒體檔。
- 舊版資產如 v3.1 暫不刪除，以便比較與回溯。
- 使用者要求的最新 CIS 規範高於 Skill 的示範敘述；若有差異先回報，不自行推測。
